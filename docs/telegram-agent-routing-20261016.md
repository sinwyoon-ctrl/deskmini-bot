# 텔레그램 모델 호출과 공유 대화 — 2026-10-16

`코덱스야 …`, `클로드야 …`로 답할 모델을 고른다. 이름 없는 후속 메시지는 마지막에 고른 모델로 보낸다. 각 모델의 마지막 작업은 따로 보존한다. 프로젝트를 모르면 등록된 프로젝트를 물어보며, 임의 경로나 다른 프로젝트를 선택하지 않는다. 두 설정에 같은 `conversation_project`가 있는 경우에만 프로젝트를 이어서 찾는다.

실제 모델 발언은 `[코덱스]`·`[클로드]`, 접수·상태·실행 승인 알림은 `[봇 안내 · 모델]`, 일반 비서 답변은 `[비서 답변]`으로 표시한다. 모델 질문 출처는 발행 시 불변 기록으로 남겨 인계 뒤에도 바뀌지 않는다. 기존 Codex 질문은 질문 메서드로, 기존 native 완료 결과는 해당 dispatch의 실제 시도 기록으로 판별한다. 출처가 없는 과거 native 질문은 미확인으로 취급한다.

`클로드가 대화 넘겨받아`, `코덱스 너는 어떻게 생각해?`는 같은 방의 최근 기록을 참고한다. 최근 최대 24개·본문 합계 6,000자·항목 1,500자를 읽으며 생략 여부를 표시한다. 전송 완료 기록만 포함하고 비밀값은 가린다. 기록은 JSON 참고 데이터이고 승인이나 작업 소유권이 아니다. 이전 완료 결과도 현재 사용자 요청과 분리한다. 현재 요청은 잘라내지 않고 길이를 넘으면 거절한다.

질문 카드에 답장하면 원래 질문의 모델·작업으로 돌려보내고 현재 선택은 유지한다. 마지막 정식 질문 번호를 사용하므로 본문에 옛 질문을 인용해도 처리한다. 모델 이름과 질문 작성자가 다르면 어느 쪽에도 보내지 않는다. 진행 상황 조회·대화 인수·잘못된 메시지에 대한 답장은 미답 질문을 소비하지 않는다. 실행 승인은 기존 버튼으로만 받는다.

실행 중인 Claude 추가 지시는 원래 dispatch의 소유권·생존·종료 상태를 확인해 native 수신함으로 보낸다. 재전송은 같은 UUID만 사용한다. 전달 확인은 수신함 접수이며 모델의 적용 확인과 다르다. 추가 지시가 미전달이면 질문 답변도 보류한다. 종료·교체된 작업자로 자동 재전송하지 않는다. 대화 인수는 파일 작업 인계가 아니며, 직접 Codex 작업의 파일 소유권을 무관한 native 작업에 넘기지 않는다.
