# Telegram 원격 작업 — 진행 조회 분리와 실제 프로젝트 연결

2026-10-16 CEO: 메인을 끄고 퇴근해도 작업자의 질문에 답하고, 중간 현황을 정확히 알고 싶다. 다음 단계 진행 및 필요시 Claude Opus 5.5 사용 허용.

이번 완료 기준은 **현황 질문이 대기 중인 답변·승인을 소비하거나 새 작업을 만들지 않는 것**이다. 작업자는 DeskMini에서 실행되어야 하며, 메인 PC의 기존 세션이 자동 이전되는 구조는 아니다.

## 구현

- “지금 뭐 하고 있어?”, “어디까지 했어?”, “진행 상황 알려줘”, “현재 상태는?” 등을 코덱스에 새 지시로 보내지 않고 상태 기록에서 바로 답한다. 질문 메시지에 답장해 물어도 조회로 처리한다.
- 질문과 승인을 기다리는 동안에도 조회는 질문·응답·명령 테이블을 변경하지 않는다. 조회와 지시가 섞인 문장은 조회만 처리했다고 명시한다. 파일명(`status.py`)·번호별 답변은 그대로 전달한다.
- 마지막 실제 turn/tool 이벤트의 동작과 수신 시각을 별도 표에 보존한다. 도구 실행 준비와 종료, 확인 단계, 응답 종료를 구분한다. 백분율이나 확인되지 않은 원인은 추측하지 않는다.
- 연결 상태가 오래됐거나 서버 세대가 다르면 “현재 상태 미확인 · 마지막 기록”으로 표시한다. 다른 채팅의 질문을 이용한 조회는 차단한다.
- 선택한 작업을 우선 표시한다. 명시적으로 다른 등록 프로젝트를 말하면 새 별도 대화에 연결하고, 기존 작업과 질문은 보존한다.

## 실제 작업공간

등록 프로젝트 `bot` / 표시 이름 “텔레그램 봇”은 운영 사본과 분리된 개발 worktree다.

`/home/ionenet/orca/workspaces/deskmini-bot/telegram-progress-20261016`

예: **“코덱스로 텔레그램봇 README를 읽고 요약해줘.”**

이 공간 안의 요청한 소스 작업만 허용한다. 운영 DB·자격증명·설치·서비스·다른 프로젝트·커밋·push·배포 권한은 주지 않았다. 기존 Orca 작업을 가져오는 기능과 구분한다.

## 검증

- 회귀 시험 **447건 통과**. 조회 중 질문 PENDING/명령 불변, 별도 작업의 질문에 대한 현황 조회, 실제 이벤트 표시, 연결 만료, 파일명·번호 답변, 혼합문장, 다른 채팅 정보 보호와 Claude 시험 자료·리소스 보존을 포함한다.
- 실제 Codex + 임시 DB + FakeTelegram **18개 시나리오 통과**. 완료 뒤 조회·결정 대기 중 조회·승인 대기 중 조회·재시작 뒤 조회에서 새 명령 0. 선택 답변과 긴 문장 답변은 같은 작업에 전달됨을 확인했다. 근거: `telegram-progress-final-20261016.json`·`.jsonl`.
- 실제 봇 개발 공간에서 README 첫 제목을 읽고, trial에서 bot으로 연결을 전환한 뒤 조회하는 **2건 통과**. README 해시와 Git 상태 유지. 근거: `telegram-bot-project-final-20261016.json`·`.jsonl`. 읽기 전용으로 지시한 시험이며, app-server의 실행 권한 자체를 read-only로 바꾼 시험은 아니다.
- 아스트라 보완 검토: 접두사 제거·혼합문장 구두점·focus 없는 명시 조회·파일명/번호 답변 회귀를 고치고 재시험했다. 최종 추가 필수 보완 없음.

## 범위와 남은 일

자연어 조회는 위와 같은 명시적인 현황 질문을 분리하는 규칙이며 모든 문장을 의미 분석한다고 주장하지 않는다. 복잡한 답변은 원래 질문에 답장하거나 명시적 답변 명령으로 전달할 수 있다. 모델 답변은 작업자의 보고이며, 독립적으로 제품 전체를 검수했다는 뜻은 아니다.

Telegram 전송·클릭은 모의다. DeskMini의 독립 작업으로 실행했지만 메인 PC 전원을 실제로 끄는 시험은 하지 않았다. Claude 검증은 `telegram-claude-roundtrip-20261016.md`에서 업무 질문과 CLI 실행 권한 승인을 구분한다.
