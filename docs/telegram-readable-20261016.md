# Telegram 응답 가독성 개선 — 2026-10-16

CEO 요청: “지금은 너무 기계어 같고 이해하기 힘든 경우가 있어.”

기준: 현재 상황을 먼저 말하고, 대표가 해야 할 행동을 그다음에 적는다. 접수·실행·승인 대기·응답 종료를 구분한다. `ux-copy` 기준을 적용했으며, 표시 문구는 별도 LLM 호출 없이 바꿨다.

## 바뀐 표시

- 코덱스 메시지 첫 줄은 프로젝트 이름. 긴 대화 번호는 하단으로 이동했다.
- 상태 코드 대신 “다음 요청 대기”, “답변을 기다리는 중”, “현재 진행 상태 확인 필요”처럼 표시한다. 조회 시각은 한국 시간으로 보여 준다.
- 승인 내용은 통째 JSON 대신 “확인이 필요한 이유 / 실행할 명령 / 작업 폴더 / 추가로 요청한 권한”으로 나눈다. 명령·경로·권한의 실제 값과 알려지지 않은 필드는 보존한다. 복잡한 권한 값은 정확성을 위해 원문 구조를 유지한다.
- 권한 승인은 이번 요청의 작업이 끝날 때까지 유효하며, 같은 요청 안에서 여러 번 사용될 수 있다고 명시한다. 명령·파일 준비 알림은 승인 전 실행을 단정하지 않는다.
- 질문은 선택지 설명과 답장 방법을 함께 보여 준다. 여러 질문에는 `1. 답변` / `2. 답변`으로 답할 수 있고, 기존 JSON 입력도 계속 지원한다.
- 오류는 발생한 상황과 다음 행동을 먼저 안내하고 상세 내용은 아래로 뺐다. 연결 복구 안내는 재실행과 구분한다.
- 초기 지시가 대기 중이면 별도의 “연결 준비 완료” 알림을 생략한다. 모델의 답변도 짧은 한국어 문단·목록으로 쓰도록 시작·복구 지침을 보강했다.
- `/status`, `/tasks`, Orca 조회의 작업 상태·조회 시각도 정리했다. 개별 Orca 작업 상세 조회에는 실행 식별자를 남겼다.

예시 — 실행 전 확인 카드(설명용):

```text
코덱스 · 연결시험

실행 전에 확인이 필요합니다.

python -m unittest

작업 폴더
<해당 작업 폴더>

[이번만 허용] [허용 안 함]
```

## 검증

- 회귀 시험 **430건 통과**. 승인 범위·허용되지 않은 선택·만료·중복 처리·새 답장 형식과 기존 형식·다중 질문 번호 검증을 포함한다.
- 긴 질문에서도 확인 번호와 대화 번호를 보존한다. 실제 표시된 3,500자 메시지에 답장했을 때 현재 선택한 작업과 관계없이 원래 질문으로 연결되는 시험을 추가했다.
- 아스트라 보완 검토에서 찾은 식별자 잘림·권한 유효 기간·승인 전 실행 단정을 수정했고, 재검토에서 추가 필수 결함 없음.
- 실제 Codex를 사용하는 격리 자동 시험 **14건 통과**. 최종 근거는 `telegram-readable-final-20261016.json`·`.jsonl`. Telegram 전송과 버튼은 모의이며, 운영 대화에는 시험 입력을 보내지 않았다.

## 운영 반영

코드 커밋 `6b0394b`를 main에 반영하고 chief·Codex bridge를 재시작했다. 반영 직전 실행 중인 작업·대기 승인·전달 중 지시가 없음을 확인했다. 세 서비스가 active이며, 기존 대화는 같은 thread로 복구했다. 마지막 응답 해시와 trial 파일 내용·수정 시각이 유지되었고 새 작업 지시는 제출하지 않았다. 증거는 `telegram-readable-production-20261016.json`이다.

## 적용 범위

표시 문구·질문 답장 형식을 수정했다. 승인 없이 자동 실행하거나 새 권한을 주는 변경은 없다. 모델 답변의 문체는 지침으로 유도하며 모든 답변 문구를 고정하지 않는다. 휴대폰 화면의 실제 레이아웃은 이번 시험에서 직접 확인하지 않았다.
