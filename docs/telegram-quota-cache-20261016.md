# Telegram 사용량 조회의 중복 CLI 호출 제거

2026-10-16 · Codex 구현·검증. 기준 커밋: `86eaa49`.

사용량 기록이 없을 때 Claude 사용량을 연속으로 물으면 각 요청이 큐에 들어간다.
기존 코드는 입력 시점에만 캐시를 확인해, 앞선 조회가 수치를 확보한 뒤에도
뒤의 요청마다 CLI를 다시 실행했다. 격리 재현에서 연속 조회 3건은 CLI 3회였다.

`process_one`이 Claude 사용량 요청을 처리하기 직전에 기록을 다시 확인하도록 했다.
60초 이내의 유효한 관측 기록이 있으면 이를 답하고, 없으면 기존 CLI 조회를 실행한다.
앞선 일반 Claude 대화에서 얻은 관측 기록도 같은 방식으로 재사용한다.
각 원래 요청에는 별도 outbox 응답이 남으며, 일반 대화·프로젝트 지시·결정 답변의
처리 경로와 캐시 유효 기간은 유지한다. 스키마·서비스 설정은 변경하지 않았다.

## 검증

- 새 회귀 시험 5개 추가. 수정 전 집중 시험은 20개 중 3개 실패했고,
  수정 후 집중 시험 20개와 전체 회귀 시험 546개가 모두 통과했다.
- 연속 조회 3건: 모의 CLI 호출 3회 → 1회, 응답 3건 유지, 재처리 시 추가 호출·응답 없음.
- 앞선 일반 대화의 수치를 뒤의 조회가 재사용함을 확인했다.
- 61초 지난 기록은 다시 조회하고 새 수치를 답함을 확인했다.
- 최신 사용량 기록이 있어도 Codex·Claude 일반 대화는 각각 모델을 호출함을 확인했다.
- 대기 중인 질문·추가 지시 큐·선택 작업이 캐시 조회 전후에 유지됨을 확인했다.

시험은 격리된 DB·모의 CLI·FakeTelegram을 사용했다. 실제 네트워크 요청 수나
휴대폰 응답 시간을 측정한 결과는 아니다. 최초 전체 시험의 환경 오류 2건은
사본에서 빠진 SYSTEM_SPEC.md를 추가하고, 홈 아래 임시 폴더를 요구하는 기존
시험을 승인된 실행 환경에서 다시 실행해 해소했다. 최종 전체 결과는
`Ran 546 tests in 10.729s / OK`다.

이 변경은 개발 브랜치에 저장하며 서비스 재시작·운영 DB 변경·원격 push는
수행하지 않는다. 기존 연속성 시험 `CONTINUITY-20261015-01`과 그 파일은 유지한다.
