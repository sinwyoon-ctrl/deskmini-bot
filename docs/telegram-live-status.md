# Telegram 실제 Orca 세션 조회 — 2026-10-16

기존 봇은 `orca_requests`의 감독 발주 기록만 조회해 모바일에서 시작한 Codex 세션과 실제 마지막 응답을 놓쳤다. 기존 bridge timer가 고정된 DeskMini CLI의 `worktree ps --limit 12 --json`을 읽고, 같은 runtime ID를 확인한 뒤 별도 `orca-sessions.json`을 원자적으로 저장한다. 명령 타임아웃은 8초이며 조회 실패는 기존 성공을 현재값으로 유지하지 않는다.

`/orca status`, `/status`, “지금 누가 작업 중이야”와 자연어의 Orca 조회에 이 관측을 연결했다. 원래 감독 발주와 직접 실행·질문·답변 상태는 변경하지 않는다. 캐시는 120초 이내 관측만 표시하고, 누락 호스트·잘린 목록·실패·오래된 관측을 구분한다. 에이전트의 `done`은 응답 완료·다음 지시 대기로 표시하며 프로젝트 전체 완료나 마지막 발언의 독립 검증을 주장하지 않는다. 터미널 생존 미확인도 별도 표시한다.

봇 서비스의 파일·실행 권한과 사용자 인증은 유지한다. 대화·조회는 읽기 전용 캐시를 사용하며 임의 경로·명령·호스트를 받지 않는다. 관측할 때 전체 프롬프트·도구 입력·인증정보는 저장하지 않고, 마지막 응답은 기존 마스킹과 길이 제한을 적용한다. 이 관측은 세션의 중단·추가 지시·질문 답변 권한을 부여하지 않는다.

검증: 최종 전체 376시험 통과(추가 Telegram 경로 시험 포함 세션 관련 12시험). 실제 CLI 읽기 시험에서 모바일 `hammerhead`와 아이원24의 두 Codex 세션을 확인했다. 운영 DB 복사본으로 `/status` 2845자와 자연어 스냅샷의 실제 세션 포함을 확인했다. 실제 Telegram 송신이나 작업자 입력은 시험에서 수행하지 않았다.

교차검토: 무료 REST Gemini gemini-3.5-flash-lite가 필수 결함 없음을 보고했다. 선택 제안의 반환 형식 의문은 `_orca`가 기존과 같은 `(items, scope)` 튜플을 반환하고 호출부·시험이 이를 확인하므로 코드 변경 없이 해소했다. 검토 모델은 시험을 실행한 주체가 아니다.

다음 사용자 확인: 텔레그램에서 `/orca status` 또는 “지금 누가 작업 중이야”를 보내 실제 응답을 확인한다. 자동 중간 알림, 모바일 세션에 대한 Telegram 추가 지시·판단 답변은 이번 수정 범위 밖이다.
